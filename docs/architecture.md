# Architecture

## Request lifecycle

`POST /api/dossier` accepts artwork metadata, `claimedProvenance`, and a `riskFocus`. The handler validates the request with Zod and returns newline-delimited JSON progress events, followed by either a dossier or an error event.

| Stage | Implementation | Behavior |
| --- | --- | --- |
| Query planning | `lib/queries.ts` | Builds up to ten queries from artwork identity, up to five parsed owner/name fragments, and focus-specific vocabulary. |
| Search | `lib/exa.ts` | Runs Exa searches in parallel with up to six results per query. Individual failures are logged and reported as zero results. |
| Ranking | `lib/exa.ts` | Normalizes URLs, merges duplicates, and ranks by query hits, highlight count, and provider score. |
| Page retrieval | `lib/exa.ts` | Requests up to 4,000 characters of text and intent-shaped highlights for the top eight URLs. Search highlights remain usable if the content fetch fails. |
| Synthesis | `lib/extract.ts` | Sends up to four highlights and 1,500 characters of text per source to OpenAI Chat Completions in JSON mode. |
| Structural validation | `lib/extract.ts`, `lib/schema.ts` | Normalizes fields and enum values, then parses with Zod. The model call uses JSON mode, not strict schema-constrained generation. |
| Citation filtering | `validateCitations` in `lib/extract.ts` | Filters IDs against the current run's source list and removes or downgrades selected uncited output. |
| Presentation | `components/Workbench.tsx` | Consumes the stream, displays progress, and renders the dossier with links to sources. |

Source IDs such as `S1` are assigned within each request. They are not stable identifiers across runs. The final source list is assembled by the server rather than generated by the model.

## What citation filtering enforces

- Source IDs that were not retrieved are removed.
- Timeline events without valid citations are removed, except explicit `unknown_gap` entries.
- `supported`, `partially_supported`, and `contradicted` claim checks without valid citations become `needs_review`.
- Risk flags without valid citations are removed, except `none_found`.

The filter does not check whether the cited passage entails the claim, whether two sources refer to the same artwork, or whether the source itself is reliable. It leaves the summary and next actions unchanged. Source categories are inferred from URL and title heuristics; risk and confidence labels are not calibrated scores.

## Failure behavior

Malformed input returns a JSON error before streaming begins. Missing Exa configuration also returns a JSON error. No retrieved sources produces an error event rather than a dossier.

Missing OpenAI configuration, a failed model request, or invalid model output triggers a fallback. It includes retrieved sources, marks submitted claims `needs_review`, and states that automated synthesis was unavailable. Its default `medium` risk label is a fallback value, not an assessment of the artwork.

Once streaming has started, errors are represented in the event stream. Consumers must inspect events even when the HTTP response is successful.

## Data and deployment

The app has no database or application-level dossier persistence. The browser holds the active run in component state. Exa receives generated queries and requested URLs; OpenAI receives artwork metadata, claimed provenance, and selected retrieved excerpts. Provider retention and hosting logs are outside the app's storage model. Error logs may include search queries or provider diagnostics.

API keys are read from server environment variables and must not use a `NEXT_PUBLIC_` prefix. A shared deployment needs authentication, request and spending limits, and a suitable logging policy. Those controls are not implemented here.

## Repository map

| Path | Purpose |
| --- | --- |
| `app/` | Page shell, metadata, styles, and streaming API route. |
| `components/` | Artwork form, activity feed, dossier sections, and citation navigation. |
| `lib/` | Schemas, query planning, source retrieval, classification, extraction, and presets. |
| `scripts/validate-cases.ts` | Separate live retrieval diagnostics for known cases. |
| `data/validation/` | Documentation and ignored, locally generated reports. |
| `public/presets/` | Illustrative artwork thumbnails with credits in `lib/presets.ts`. |

## Evaluation boundary

The case-validation script has its own queries, schemas, case-specific rules, and optional model checks. It does not exercise the production request handler or establish general extraction accuracy. It can help inspect source coverage and identify retrieval gaps; results should be described at that scope.
